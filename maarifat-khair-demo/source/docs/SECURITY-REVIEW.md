# مراجعة الأمن السيبراني: معرفة خير (النسخة المرجعية)

التاريخ: 2026-10-17. النطاق: الخادم المرجعي، الواجهة، التشفير، التحكم بالصلاحيات، المعاينة والمطابقة، لوحة المشرف الأعلى. المراجعة ذاتية وليست بديلًا عن اختبار اختراق مستقل.

## ضوابط مفعّلة

- مصادقة متعددة العوامل لكل الحسابات، وإعادة تحقق (5 دقائق) قبل الكشف والتصدير والسحب والحذف.
- منع الوصول افتراضيًا، ورد 404 موحد لما لا يحق للمستخدم رؤيته (لا تمييز بين غير موجود وممنوع).
- فصل المهام: تعليق المشرفين وتفعيلهم وتجديد تحققهم يحتاج اعتمادًا من شخص مستقل عن الطالب.
- تشفير مغلف AES-256-GCM: مفتاح لكل قسم وإصدار، وربط AAD بالمعرّف والإصدار، ومفتاح KEK لكل ملف وطبقة. العبث بالنص المشفر أو AAD يفشل مغلقًا. حذف الملف يُتلف مفاتيحه (crypto-erasure) ويترك tombstone.
- سجل تدقيق مترابط بالتجزئة بلا محتوى، ويُتحقق من سلامته في لوحة الأمان.
- رؤوس HTTP: CSP صارم بلا inline، `X-Content-Type-Options`، `Referrer-Policy`، `Cache-Control: no-store` للواجهات البرمجية، كعكة الجلسة `HttpOnly; SameSite=Strict`، ورأس CSRF مخصص `X-MK` لكل طلب غير GET.
- حدود المعدل لكل عنوان، وحد حجم الجسم (413)، ونوع المحتوى (415)، ومهل الاتصال.
- الواجهة تبني DOM بـ `textContent` فقط، ولا `innerHTML`.
- المشرف الأعلى لا يقرأ ملفات ولا يفك مفاتيح: اللوحة أعداد وحالات فقط.
- عامل المطابقة لا يفك طبقتي الهوية والخاص.

## مخاطر متبقية (يجب إغلاقها قبل الإنتاج)

1. **KMS محاكى**: مفاتيح KEK في ذاكرة العملية. المطلوب KMS/HSM حقيقي مع فصل إدارة المفاتيح عن إدارة التطبيق.
2. **HPKE غير منفّذ**: التغليف للمشرف عند الإيداع المختوم يحتاج مكتبة HPKE مدققة (RFC 9180).
3. **التخزين في الذاكرة**: لا قاعدة بيانات، ولا نسخ احتياطي حقيقي. استعادة النسخ تحتاج إعادة تطبيق tombstones.
4. **MFA بـ TOTP فقط**: يُنصح بـ WebAuthn/Passkeys للأدوار الإدارية.
5. **المتصفح التجريبي**: نسخة الصفحة المنشورة تشغّل الخلفية داخل المتصفح مع scrypt بتكلفة منخفضة (N=2048). هذا للعرض فقط ولا يُستخدم في الإنتاج. الخادم الحقيقي يستخدم القيم الافتراضية في Node.
6. **تحديد المعدل في الذاكرة** لا يصلح لعدة نسخ خادم. يلزم مخزن مشترك.
7. **المراجعة القانونية**: لم تُقرأ تعديلات اللائحة التنفيذية لنظام حماية البيانات الشخصية المطروحة للتشاور في أكتوبر 2026. تحتاج مراجعة محامٍ مختص قبل الإطلاق، وكذلك تقييم أثر الخصوصية.
8. **اختبار اختراق مستقل** وتحليل تبعيات (الخادم بلا تبعيات خارجية، والنسخة المتصفحية تضم noble وbuffer).

## ملحق الإصدار 3 (التبسيط إلى ثلاثة أدوار)
- أُزيل TOTP؛ الدخول باسم + رقم عشوائيين (72 بت للرقم) مخزّنان بـ scrypt، قفل لكل اسم بعد 5 محاولات، إعادة إدخال الرقم للعمليات الحساسة، زمن موحد لوجود الاسم وعدمه.
- لا حسابات للمستفيدين: خطر جديد هو صحة إقرار المشرف بالموافقة. المخففات: مرجع إثبات إلزامي، تجديد دوري كل 90 يومًا، سجل تدقيق، وإلغاء يتلف المفاتيح. **يلزم رأي قانوني (نظام حماية البيانات الشخصية) قبل الإنتاج.**
- كل الصفحات الثابتة غير المصرح بها تعيد 404 موحدًا؛ النسخة المنشورة كأداة عرض ثابتة (Artifact) لا تحجب لأنها رابط خاص بلا خادم.
- المشرف الأول لا يقرأ ملفات المستفيدين؛ لوحته أعداد وحالات.
- يبقى: WebAuthn للإدارة، KMS/HSM حقيقي، قاعدة بيانات، اختبار اختراق.
- `npm test`: 42 اختبارًا ناجحًا.
